# שרת MCP של לידרפיד

מאפשר לשאול את המאגר של לידרפיד **ישירות מהצ'אט**, בלי לפתוח את האתר.

## מה זה נותן

שלושה כלים:

| כלי | מה הוא עושה | זמן | עלות |
|---|---|---|---|
| `ask_leaderfeed` | שאלה בעברית → תשובה כתובה עם מקורות ממוספרים | 25-40ש' קר, מיידי מהמטמון | ~5-10 אג' · 0 מהמטמון |
| `search_news` | חיפוש בארכיון → רשימת כתבות | 1-4ש' | **0** (בלי AI) |
| `city_dossier` | תדריך אזור על עיר | 20-40ש' קר | ~10 אג' |

הערך האמיתי הוא **שרשור**: "תכין תדריך על נהריה, תצליב עם מה שקרה שם החודש, ותכתוב מזה הודעת וואטסאפ" — משפט אחד במקום חמישה מסכים.

## התקנה

```bash
cd mcp && npm install
```

ואז להוסיף את השרת. ב-Claude Code:

```bash
claude mcp add leaderfeed -- node C:/Users/ori19/Documents/news-generator-deploy/mcp/server.mjs
```

או ידנית בקובץ ההגדרות:

```json
{
  "mcpServers": {
    "leaderfeed": {
      "command": "node",
      "args": ["C:/Users/ori19/Documents/news-generator-deploy/mcp/server.mjs"]
    }
  }
}
```

צריך להפעיל מחדש את הצ'אט אחרי ההוספה.

## בדיקה שהכל עובד

```bash
cd mcp && npm run smoke
```

מריץ את השרת בפרוטוקול האמיתי, קורא לשלושת הכלים מול הפרודקשן, וכותב את התוצאה ל-`smoke-out.txt`. אמור להראות `tools: 3` ותשובה לכל אחד.

## החלטת תכנון: למה HTTP ולא ייבוא ישיר

השרת **קורא לנתיב `/api/ask` שכבר רץ בפרודקשן** במקום לייבא את `src/lib/ask.ts`.

ייבוא ישיר היה דורש לקוח סופאבייס שני, לקוח אנתרופיק שני, עותק של כל משתני הסביבה ושלב בנייה של TypeScript — ושני המסלולים היו נסחפים זה מזה ברגע שאחד מהם מתוקן. דרך ה-HTTP, תשובה בצ'אט היא **אותה תשובה בדיוק** שהאפליקציה נותנת, מעצם הבנייה, והיא יורשת בחינם גם את התקרה היומית וגם את המטמון של שש השעות.

## הערות

- **`LEADERFEED_URL`** מאפשר להצביע על סביבה אחרת (ברירת מחדל: הפרודקשן).
- **המכסה היומית משותפת** עם האפליקציה. שאלה מהצ'אט נספרת כמו שאלה מהאתר.
- **ל-`search_news` חשוב להעביר שם נקי בלי אות שימוש מחוברת** — `שיכון ובינוי` ולא `בשיכון ובינוי`. החיפוש מבוסס תת-מחרוזת, ותחילית מחוברת מרוקנת אותו. תיאור הכלי כבר אומר את זה למודל.
